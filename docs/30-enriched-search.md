# 收藏搜索

侧栏和 Cmd/Ctrl+K 是统一入口；X、GitHub 收藏页仅保留页头右侧的筛选。搜索弹层与完整结果页使用相同的接口、来源筛选、结果布局和匹配规则。

## 匹配字段

| 来源 | 可搜索内容 |
| --- | --- |
| 普通链接 | 整理后的 title、原始 meta_title、note、meta_description、URL、域名、短链、分类和标签 |
| X | 上述字段，加正文、作者名称和账号、帖子 ID、语言、话题、提及、展开链接、引用帖内容、图片/视频/GIF 类型、回复/引用/转发类型 |
| GitHub | 上述链接字段，加当前与原始仓库名称、语言、许可证、topics、默认分支、README 路径和完整正文，以及历史 AI 简介/功能/场景/技术栈/主题 |
| 想法和待办 | 标题、正文、摘要、标签、emoji |

只使用已存储且属于当前用户、对应当前 URL 的公开采集结果。未采集到的字段不推测；不索引 draft、凭据、模型供应商、媒体源 URL。结果中的来源、媒体类型、语言、star 数、分类和标签提供上下文，搜索不加载或播放媒体。

## 规则和排序

- Unicode NFC、小写、空白合并。空格分隔的关键词共同匹配同一条记录，可以分布在不同字段；例如 `@作者 视频`、`仓库名 TypeScript 某个 README 关键词`。
- 每个词都是字面子串，`C++`、`%_`、`@name` 等不作为正则或 SQL 操作符。重复词只计算一次，不使用引号或布尔查询语法。
- 整个查询精确命中标题、标题前缀、标题子串时优先；其余按各词命中的字段权重累加排序。字段顺序为标题、身份/URL、标签/属性、备注/简介、正文；时间和 id 保证分页稳定。
- `models/search.ts` 负责字段提取、排名和高亮；D1 共享 SQL 实现相同语义。链接/想法 REST 查询复用匹配条件并保留自己的排序选项。

## 结果和键盘

- 标题优先显示整理后的 title，原始标题在桌面辅助展示；note 优先显示为简介。正文和 README 命中返回有界片段，突出各个关键词，避免重复显示标题和备注。
- 统一来源图标与紧凑结果行，不在弹层内堆叠灰色卡片。来源筛选支持网页、X、GitHub、想法和待办，并显示数量。
- 弹层上下键选择、Enter 打开、Esc 关闭并恢复入口焦点。链接打开原网站，想法/待办打开应用详情。复制短链、打开分类保留独立 Tab 操作。
- 完整结果页上下键选择，Home/End 到首尾结果，Enter 打开，Esc 返回。来源与关键词保留在 URL；查看全部结果保留来源筛选。中文输入法组合输入不触发结果打开或关闭弹层。
- 请求防抖、取消、迟到响应隔离；加载、无结果、错误分开，错误可重试；历史索引更新单独显示进度状态并自动继续查询。分页默认每页 20 条。

## 索引与运维

`POST /api/search` 仅接受当前登录用户，忽略客户端所有者；请求上限 16 KiB，关键词最多 2000 字符，每页最多 50 项，每用户每分钟 120 次。响应 `private, no-store`，不输出全文 README 或内部采集字段。

`search_documents` 保存用户隔离的规范化投影。触发器递增 revision；只重建脏记录，CAS 避免覆盖并发更新。查询使用用户索引和 INSTR；多关键词经 JSON 参数传入，避免关键词数量耗尽 SQL 参数。它不是倒排全文索引，候选扫描范围仍为当前用户的收藏。

迁移 0028 建表、注册触发器；0029 将 links.title 纳入失效；0032 使已有投影重新生成来源和媒体类型等新字段。0032 在新版部署后执行，再用新版代码运行 `bun run scripts/backfill-search.ts`，避免旧版本重建时遗漏新字段。随后确认 `indexed_revision <> revision` 为零。脚本只输出进度，不输出用户内容。

## 验证

真实 SQLite 验证跨字段 AND、模型/SQL 排名一致、分页计数、重复词、大量词、更新/删除失效、租户隔离与 Unicode。HTTP 验证完整 README、整理后的 title/note 和跨字段查询；浏览器验证弹层和结果页键盘、中文输入法、来源切换、窄屏、主题、无结果和错误恢复。发布由标准 release 脚本执行完整 L3，提交与推送正常执行质量钩子。
