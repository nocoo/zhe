# 统一链接整理

普通链接、Inbox、文件夹、GitHub 收藏和 X 收藏使用同一个 AI 整理任务、ViewModel 和弹窗。本文取代 24、27 中旧的双流程整理说明。

## 共享字段

`links.title` 是可空的整理标题；`links.note` 是可人工修改的整理备注。原始 `metaTitle`、`metaDescription` 和来源快照独立保存，采集更新不覆盖整理字段。所有卡片优先显示 title，辅助显示原始标题；描述优先 note，原始简介弱化。相同文本去重。X 的 note 使用无标题栏的等宽批注，纯链接帖子也不拿 note 代替文章标题。标题一行，备注最多两行（列表一行），原简介一行；文字可点击展开。搜索同时匹配整理与原始字段。

新增、编辑、API、CLI、导入和备份均支持 title。备份格式版本 3，旧导入默认 title=null。CLI `create/update --title` 对应整理标题，`update --meta-title` 编辑原始标题，`--desc` 仍编辑原始简介。

## 一次整理

`POST /api/ai/suggest-link-org` 只接收 linkId，服务器读取当前用户拥有、且 source_url 与当前 URL 一致的资料。提供 URL、原始标题/简介、当前标题/备注、当前分类标签、目录，以及已有 GitHub 仓库/完整 README、X 正文/引用/媒体资料。不存在的资料不阻止整理；README 有全文就提供全文，不能静默裁剪。媒体 URL 不代表模型已经识别画面。历史 AI 结果作为已有上下文，不是独立事实依据。

只有 `lib/ai/tasks/suggest-link-org.ts` 定义整理提示词，通过 `runAiTask` 调用模型。统一输出 title、note、folders、tags。标题目标 12–24 字符，最多 32；备注目标 50–90，最多 120。过长或无效结果报错，不直接截断。手动备注不受 AI 生成长度限制。推荐 0–3 个已有文件夹/Inbox、0–5 个已有标签。X 原有主题分类策略保留。

客户端请求 `Accept: application/x-ndjson`，服务器返回真实阶段事件：准备、资料就绪、调用、校验、结果/错误。调用中显示已等待时间，模型回复和实际完整提示词可展开。普通 JSON 请求使用同一个任务；旧 `/api/ai/analyze-github` 仅作为该 handler 的兼容入口，不自动保存、不维护第二套生成逻辑。

模型只能推荐目录中已有的文件夹（或 Inbox）和标签；没有合适的推荐时返回空数组。不接受模型虚构的 ID、空标签 ID 或新名称。分类和标签的显示名称以实际目录为准。

弹窗全宽编辑 title/note，桌面分类和标签横排，手机纵排。所有表面保持最高层亮色，字体与间距遵循设计 token。标签横向选择，管理标签、推荐理由和运行详情按需展开，不显示字数建议或计数器；实际错误就地提示。保存操作始终可见。配置、调用、解析和保存错误保留当前草稿；关闭取消请求，晚到响应不能写入另一个链接的编辑器。

## 应用和历史资料

用户修改后点击应用，通过 `applyLinkOrganization` 保存最终标题、备注、文件夹和选中标签 ID（`tagIds`）。已有标签默认保留，取消选中表示解除关联，不删除全局标签。AI 推荐和应用操作均不能创建标签。

需要新标签时，由用户在「管理标签」输入名称并点击「创建标签」，通过现有标签 action 立即创建全局标签并选中；同名已有标签直接复用。创建后取消整理会保留该全局标签，但不会关联到链接；点击应用才保存关联。

服务端以 `search_documents.revision` 校验生成时的链接与来源版本。版本、归属、文件夹或标签不匹配时拒绝整组写入，包括生成后已删除或其他用户的标签。断言、链接更新和标签关联在同一个 D1 batch 事务中执行；任何一步失败全部回滚。GitHub 轮询只同步来源 metadata，不能用旧响应覆盖当前标题/备注。

历史 GitHub analysis 保留供统一弹窗查看。已同步到 note 的历史 summary 不再重复覆盖手动修改；历史 title 默认空，不自动消耗模型生成。0030 仅将历史 AI 标签匹配到同一用户已有标签并补全关联，不创建标签，原始 topics 保持独立。

## 迁移和验证

0029 添加 title 和搜索失效触发器；0030 关联匹配到已有标签的历史 AI 结果。迁移先于依赖字段的应用部署。开发数据库此前已应用历史同步；本轮收紧规则不删除已存在的全局标签。新库使用修订后的 0030，测试使用本地隔离 D1。

验证覆盖真实 SQLite 迁移、完整与缺失来源、用户和旧 URL 隔离、版本冲突、事务回滚、长人工备注、原始资料保留、流式事件与取消、统一弹窗，以及普通/GitHub/X 的浏览器保存和移动端布局。实际模型验证只生成建议，未应用到用户数据。
